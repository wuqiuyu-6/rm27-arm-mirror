# 关节映射标定

目标：让仿真臂的姿态与真机一致。映射式：

```
sim_q[i] = sign[i] * raw_q[i] + zero[i]        （rad）
```

`sign` / `zero` 存在 `config/joints.yaml`，是 CLI 与网页端的**唯一来源**。

## 为什么需要标定

固件发出的 `q` 是**它自己的模型**（HevRobot v1.0，`q_DH = q_URDF`）坐标；本仓库的 MJCF 来自
`model/arm_v7` 的 URDF 导出。两边虽然都叫"关节角"，但：

1. 关节轴正方向可能整体相反（URDF `axis` 约定差异）；
2. 个别关节的机械零位不同（装配 / 零点标定差异）；
3. 仿真模型的关节范围不一定覆盖实机全行程（见 README「关节范围」）。

## 已知问题：与固件标定值不一致

固件 `User/gravity/gravity_config.h` 里有一套自己的标定：

| 关节 | `position_sign` | `encoder_zero` |
|---|---|---|
| joint1 | **+1** | 0 |
| joint2 | −1 | **−1.54** |
| joint3 | −1 | **−1.66** |
| joint4 | −1 | **+1.52** |
| joint5 | −1 | 0 |
| joint6 | **+1** | 0 |

若按固件写法 `q_model = position_sign * (q_encoder − encoder_zero)`，换算到本仓库等价于：

```
sign = (+1, -1, -1, -1, -1, +1)
zero = ( 0, +1.54, +1.66, -1.52, 0, 0 )      # = -position_sign * encoder_zero
```

**现状**：实测 J2 ≈ −95°、J3 ≈ −100° 时，当前映射（全 −1 / 全 0）会让仿真臂摆到约
+95° / +100°，超出 URDF 名义范围（J2 −45°~80°、J3 0°~72°），视觉上像"折断"。
因此**怀疑 J2/J3 的 zero 差约 1.5~1.7 rad**，但尚未用参考姿态验证。

## 复标步骤（推荐，10 分钟）

### 单点法（只求 zero，sign 已知）

1. 把机械臂摆到一个**明确、可重复**的姿态（例如大臂竖直、小臂水平，或贴各自刻度）；
2. 运行：

   ```bash
   arm-mirror print --seconds 1
   ```

3. 记录六个 `raw` 值，并记下该姿态在仿真里的**期望角度**（用模型 FK 或已知刻度换算）；
4. 逐轴计算 `zero = 期望 − sign × raw`；
5. 写入 `config/joints.yaml`，`arm-mirror view` 目视确认；
6. 把姿态描述 + 六个数记到本文件（便于回归）。

### 两点法（sign 与 zero 都求）

同一关节取两个姿态 `raw₁ / raw₂`，对应期望角 `q₁ / q₂`：

```
sign = (q₂ − q₁) / (raw₂ − raw₁)
zero = q₁ − sign × raw₁
```

两个姿态间距越大越好（建议 > 45°），可避免 sign 判断错误。

## 常见坑

- **只改 sign 不改 zero**：对"整体反向 + 零位差 π"的轴，只改 sign 会得到镜像姿态，
  看起来"能对上"但端点处不对；先确认零位再定 sign。
- **用模型范围去夹实机值**：默认不夹（`--clamp` 才夹）。夹住会改变显示姿态，
  排查时不要同时开 clamp。
- **CRC 未校验**：坏帧被当数据会让臂瞬间跳一下；默认校验，只在排查时用 `--no-crc`。
- **改完没重跑前端**：网页端读的是同一份 `config/joints.yaml`，刷新页面即可生效；
  桌面端要重启 `arm-mirror`。
